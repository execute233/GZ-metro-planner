# SVG 人工校准试验

## 中文站名排版（当前查看入口）

**`network-labeled.svg`** 是带排版的 4096×4096 全网稿，保留 `network.svg` 的全部
线路路径和站点坐标。默认隐藏原图、显示白色校对背景，357 个中文站名均为可编辑文字。

- 微软雅黑：普通站 16px，换乘站 17px 加粗。换乘站按同一逻辑站点出现于多个线路图层判定，
  先于普通站分配位置。
- 根据实际字体测量占位，候选位置包括站点四周及上下错位；文字矩形同时避开线路、
  站点圆和已放置文字。字体周围有白色细描边，便于阅读。
- 本轮只有大学城南使用短引线，线路密集处的站名仍保持水平，不拆分中文站名。
  工业大道南通过调整东晓南的排版方向获得近站位置，无需跨线引线。
- `91 中文站名` 图层可以逐站编辑；`89 标签引线` 独立可编辑。
  每个文字对象保留 `label-ID` 和 `data-station-id`，位置元数据见 `data-label-box`。
- 原图仍内嵌并可打开对照；白底是 SVG 校对背景，不改变终端的深色主题或默认文字样式。

预览位于 `../../output/svg-labels/`：`network-labeled.png` 为完整 4096px 图，
`central-labels.png`、`foshan-labels.png` 为原尺寸局部图。

```powershell
python -m pip install -r tools/requirements-calibration.txt
python tools/layout_svg_labels.py --output output/svg-labels/rearranged.svg
python -m unittest discover -s tools -p 'test_svg_labels.py'
```

Windows 默认使用 `C:/Windows/Fonts/msyh.ttc` 和 `msyhbd.ttc`。其他环境需通过
`--font`、`--bold-font` 指定同一家族的字体。字体替换会改变文字尺寸，需要重新排版和检查；
SVG 不嵌入字体，也不把文字转为不可编辑的路径。

`label_overrides.json` 保存人工方向偏好，使用逻辑站点 ID 和 N/S/E/W/NE/NW/SE/SW。
`network-labeled.report.json` 保存实际文字框、方向、引线及字体信息。
生成器拒绝覆盖手工改过的输出；`--replace-generated` 仅允许替换哈希与报告一致的生成稿。
手动移动文字后，原 `data-label-box` 和报告不会自动更新，需重新校验，不能继续把旧报告当作通过证明。

本轮完成的是固定 4096px SVG 排版。终端不同缩放级别仍须在 C 渲染器中按字符单元重新避让，
不能直接照搬这些文字框。本次未更新运行时瓦片或 C 程序。

## 全网版本（当前入口）

**`network.svg`** 已覆盖当前原图/离线线网范围的全部 **21 个线路标识、357 个逻辑站点、
421 个区间**。其中 2 号线保留 `line2-full.svg` 中现有的人工编辑路径，其余线路按
4096×4096 原图重新目视标定。绘图使用手工放置的直线控制点和二次贝塞尔转弯，
没有复用旧 A* 描线。站点参考位置也单独录入，然后投影到各线路的中心线上。

- 每条线路是一个独立 Inkscape 图层，采用原图线路取样色；默认线宽为 3 像素，
  便于看见底图边缘、核对是否沿着中心线。
- `00 原图` 已嵌入并锁定，可以隐藏；`90 线路站点锚点` 可以整体或按线路隐藏。
- `network.svg` 中的 `91 独立站名` 默认隐藏，保留初始文字位置；
  排版结果在独立的 `network-labeled.svg` 中。原图图标、英文和编号胶囊仍属于底图。
- 一条线路的每个区间保留 `edge-ID`，站点圆保留逻辑站点 ID 和线路 ID。
  换乘站不同线路的视觉锚点可不同；这不产生新的逻辑站点。
- 3 号线两条分支、11 号线闭环、12 号线两个独立区段均保留。
  佛山 3 号线中山公园—联和之间的原图断口也保留，不补画连接。
- 本次范围沿用当前离线数据。原图未展开的 APM、有轨电车不额外补画；
  原图中的官桥、洪圣沙等未开通站牌仍在底图中，不额外加入现有站点 ID 集合。

已对广州中心区、北部、东部、南部、佛山区域进行全图叠加检查，并调整 11 号线
西侧与东南侧走向、广佛线沙园过渡、10 号线南段及 21 号线起点。当前状态是
**全网目视初校稿**，局部曲线半径和换乘站视觉锚点仍可进一步精修，不是像素级复刻。
这份 SVG 仅用于校准，**没有更新 `network.json` 或运行时 MBTiles**。

### 再生成与检查

```powershell
python tools/build_calibration_svg.py --output output/svg-calibration/regenerated.svg
python -m pip install -r tools/requirements-calibration.txt
python tools/preview_calibration_svg.py
python -m unittest discover -s tools -p 'test_calibration_svg.py'
```

SVG 生成器仅依赖 Python 标准库；预览工具另需 Pillow 和 resvg-py，均为离线辅助依赖。
原始手工控制点保存在 `tools/calibration_routes.py`，对应生成报告为 `network.report.json`。
报告包含原图/SVG 哈希、覆盖数量、每站参考位置投影距离；投影距离不是与原图的几何误差。

默认拒绝覆盖已有 SVG。`--replace-generated` 只允许替换哈希仍与报告一致的生成稿，
检测到手工编辑会停止。日常在 Inkscape 修改后请直接保存 SVG，保留对象 ID；
移动站点圆时仍需同步调整区间端点。拼装 2 号线时遇到 transform 会明确拒绝，
需先将变换落实为路径坐标，避免悄悄丢失编辑效果。

本次未制作 SVG → MBTiles 导入器。之后应从最终 SVG 解析编辑结果（包括曲线和变换），
经校验后按项目 schema=2 的事务流程写入数据库，不应重新运行旧自动追踪覆盖本稿。

完整版本保留了公园前、昌岗、广州火车站附近的曲线。白云文化广场的锚点改为
`(1302, 1738)`，落在线路连续的斜线中心，避免北段初稿向上方编号产生的小折角。
随后按“换乘站尽量靠中心”的要求，将完整版本中的换乘锚点向整个组合标记中心调整，
相邻区间端点同步移动。广州火车站采用三个编号的中部；公园前、海珠广场、昌岗、
江泰路、东晓南、南洲采用上下编号之间的位置；广州南站、石壁、嘉禾望岗兼顾横向中心。
白云文化广场原锚点已接近组合中心，保持不变。

普通站仍沿原线路中心。广州南站—石壁段为连接两个中心，向右平移约 17 像素，
石壁至会江以平滑曲线接回原线，避免中心锚点产生短促折返。
这是居中与原图走向之间的局部取舍；完整版本不再强制选择 2 号线编号胶囊中心。

## 图层

1. 原图：锁定，作为描图底稿。
2. 旧自动描线：默认隐藏，橙红色；打开可与新描线比较。
3. 校准线路：洋红色细线，便于观察是否沿着原图蓝线中心；不是最终线路配色。
4. 站点视觉锚点：洋红色空心圆。
5. 独立站名：默认隐藏，避免与原图文字重叠；可单独移动文字。

在 Inkscape 的“图层与对象”面板中切换可见性。选中第 3 层并缩放到选区，
即可定位试验区域（约 x=1114–1575、y=1465–1994）。用节点工具编辑线路。
关闭原图层，可以检查纯矢量几何。不要缩放整个图层或改变画布尺寸。

## 标注约定

- `edge-47` 至 `edge-54` 对应现有区间 ID；`data-from-id`、`data-to-id`
  和 `data-line-id` 保存连接关系。注意：2 号线的内部 line ID 是 3。
- `station-47-line-3` 等圆的 `cx/cy` 是该线路的视觉锚点。
  原图使用编号胶囊而非单个站点圆；换乘站选择 **2 号线编号胶囊中心**。
  这不等同于多线路换乘标记的统一中心，也不改变逻辑站点 ID。
- 每条 path 表示相邻站点之间的区间。普通区间采用直线；广州火车站北侧
  采用三次贝塞尔曲线表达原图的转弯。曲线仍须人工复核。
- 标签与站点分离；移动文字不能改变站点位置。
- 移动站点圆时，必须同时调整相邻 path 的端点。SVG 编辑器不会自动联动。
- 保留对象 ID。后续导入器需处理 path 曲线离散化、编辑器产生的 transform、
  端点连续性和换乘站视觉锚点，不能直接将 SVG 当作当前 network.json 导入。
